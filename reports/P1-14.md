# Báo cáo P1-14 — Archive catch-up, prefetch, spool tràn
Trạng thái: PASS

## Kế hoạch
Hiện thực cơ chế Archive catch-up, prefetch và spool phân tầng tràn sang bucket theo spec/02 §9 và spec/design.md §1, §3:
1. Spool phân tầng (Tiered Spool) và tràn sang Bucket (MinIO):
   - Cài đặt backend lưu trữ bucket staging (MinIO / S3) qua chuẩn HTTP REST trong `internal/spool/bucket.go`.
   - Khi dung lượng tầng local (Pebble) đạt `LocalHardLimit`, các transaction tiếp theo tự động tràn sang bucket staging trên MinIO.
   - Khi mọi tầng spool chạm hard limit (`TotalHardLimit`), báo lỗi ngay lập tức với mã `prefetch_exhausted` (exit code 5).
   - Thống kê `Usage()` phân tách chính xác `LocalBytes` và `BucketBytes`.
2. Prefetch và Archive Catch-up:
   - Module `internal/reader/archive` đọc binlog archive từ thư mục/storage.
   - Module `internal/seed/prefetch.go` điều phối prefetch nền:
     - Mặc định bật prefetch: đọc từ P vào spool song song với restore. Nếu archive bị xóa giữa chừng, catch-up vẫn hoàn tất đầy đủ nhờ dữ liệu đã được prefetch trong spool.
     - Nếu tắt prefetch và archive bị xóa / thiếu log giữa P và source position, báo lỗi `log_gap` (exit code 5).

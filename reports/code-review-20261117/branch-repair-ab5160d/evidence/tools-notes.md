## Root final-review follow-up: directory ownership guard

`privateDir` no longer chmods an arbitrary existing output directory. It rejects an existing directory unless it is owned by the current effective user and already 0700. It checks every path component with Lstat and rejects symlink targets or parents before creating descendants. Missing components are created 0700; chmod is limited to directories this call successfully created (to handle an unusual umask). Existing public or unowned directories are left unchanged. README/report03 reflect this guard.

PASS `/usr/local/go/bin/go test -race ./tools/diagnostics/pg-strict`, log `/tmp/strand-repair-private-dir-tests.log`. Added regressions: an existing0755 directory is rejected with mode/content unchanged, symlink target and symlink parent cause no permission changes or escaped child creation, and a fresh nested path is0700 and can be reused as an owned private directory. Existing atomic config-file overwrite/symlink tests remain separate and pass. No additional live PG/browser run was needed or performed for this bounded guard fix.

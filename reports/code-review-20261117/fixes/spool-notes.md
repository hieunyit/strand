Sidecar file accounting is recorded before the potentially ambiguous transaction commit. A referenced file missing or changing size causes a safe error when verified; unreferenced files stay charged until physically removed. The spool never deletes borrowed sidecars. Usage and capacity-pressure checks refresh the index against the filesystem.

Existing databases migrate by scanning local and bucket transactions; migration fails if required bucket data or referenced files are unavailable. It also scans the standard <spool dir>/spill tree for previously unindexed retained files. Older unreferenced files outside that standard tree are undiscoverable because older spool state never recorded their paths. Decoded bucket segments are cached across consecutive transaction references during migration.

## Confirmed findings, fixed in working tree

1. **P1: breaker status export leaked query continuations and row data.** `tools/diagnostics/breaker/sanitizer.go` formerly filtered only individual SQL-keyword-bearing lines. An INSERT followed by `VALUES ('card-sensitive-sentinel')` exported the entire continuation; InnoDB `0: len ...; hex ...; asc supersecret;;` records also survived. Such records occur in FK/deadlock diagnostics and are arbitrary user data. Executable reproduction `/tmp/strand-breaker-repro.go` confirmed leakage before the fix. Fixed by exporting a conservative allowlist of complete numeric status lines and fixed section labels; arbitrary raw SQL, physical records and free text are omitted. Log/I/O counters and numeric semaphore diagnostics remain available. Regression `TestEngineStatusOmitsMultilineQueriesAndRecordDumps` covers multiline INSERT, WITH, CALL, comments, hex and ASCII records plus retained counters/semaphore info. Full arbitrary engine text is intentionally no longer exported.

2. **P2: protected snapshot did not enforce protection when replacing existing paths.** `tools/diagnostics/breaker/collector.go:322` formerly called `os.WriteFile(...,0600)` directly. Reproduction confirmed existing mode0644 remained0644 and an existing destination symlink caused its target to be overwritten. Hardlinked aliases were also modified. Fixed via0600 sibling temporary file and atomic rename (`SaveProtectedArtifact` at line337); telemetry analysis output in `tools/diagnostics/breaker/cmd/main.go` now uses the same helper. Tests prove private final mode, correct JSON and preservation of symlink/hardlink targets. Parent directories remain operator-selected; this does not defend against a hostile actor replacing ancestor directories, and no claim of race-proof ancestor confinement is made.

3. **P1: breaker DSN redactor exposed valid MySQL passwords.** New executable `/tmp/strand-dsn-repro.go` used the actual driver's parser to establish that `:diagnostic-password@tcp(localhost:3306)/db` and `u:p@partial-password@tcp(localhost:3306)/db` are valid. Old redactor printed the first password entirely and the second password suffix. This affects the command's connection announcement and collector's `RedactedDSN`. Fixed `tools/diagnostics/breaker/sanitizer.go:16` to follow driver delimiter grammar (last slash, preceding last@, first credential colon), validate input, and fail closed for malformed strings. Tests include empty username and passwords containing@, colon, slash and://.

4. **P2: tuning read-modify-write lost concurrent independent updates.** The newly added save mutex covered `saveConfigContent`, but `saveTuning` read/applied changes before acquiring it. Five concurrent independent changes returned success while only one survived. Original-source Go overlay reproduction `/tmp/strand-tuning-before.log` shows four fields lost. Fixed `internal/web/tuning.go:541` to hold the mutex throughout read/apply/save and factored `saveConfigContentLocked` in `internal/web/configedit.go:255` to avoid nested acquisition. Concurrent regression preserves all five independent fields. This is an incomplete hardening of a preexisting read-modify-write race, rather than a new race introduced by e3d19bb.

5. **P2: tuning endpoint bypassed new editor request-size limits.** `apiTuningSave` decoded unrestricted JSON while adjacent config endpoints cap bodies. Valid JSON with1MiB of whitespace in a duration string returned200 and wrote config on original source; same original overlay log confirms it. Fixed `internal/web/tuning.go:511` with the same1MiB MaxBytesReader bound, regression now expects400. This gap existed before the branch and remained after its request-bound hardening.

# Data correctness review

Fixed confirmed source UNIQUE prefetch identity bug at the parent's request. Source catalog resolution previously supplied the UNIQUE columns through `TableInfo.PK`, while prefetch stamped every source contract `pk`. A source-only prefetch on a UNIQUE NOT NULL table could therefore succeed and cover GTIDs, but consuming sync rejected its persisted contract against mode `unique`. FULL table maps without primary metadata also skipped catalog lookup entirely. The fix carries the catalog's selected identity mode to prefetch, looks up unique identity for FULL table maps, checks catalog column names and types against the map, and refuses unknown provenance. Catalog metadata still cannot prove an index existed at a historical binlog position; this limitation is documented.

Focused checks passed: `go test ./internal/reader/mysql ./cmd/strand ./internal/pipeline -run 'TestPrefetchTableMap|TestSourceUniquePrefetchIdentitySpoolRoundTrip|TestPrefetchConsumerChecksNamesOrderModeAndGeneration' -count=1`. Tests cover minimal and FULL map resolution, name mismatch, STX4 spool roundtrip, and consumer compatibility including mismatches. They do not exercise a live source-to-sync roundtrip. I inspected identity/STX4, prefetch, reader and snapshot diffs, keyless handling and constraint validation; review was not exhaustive, especially archive parsing and live database timing. No other confirmed new findings.

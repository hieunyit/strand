# Branch data review — five findings

All paths below are relative to `/home/hellc/strand`, branch head `ab5160d`. Severity reflects the reachable impact, not test completeness.

1. **P1 — Archive spool identity is never compared with the consuming pipeline's key.** `internal/reader/archive/schema.go:210-222` validates only the number of key values against the sidecar; `cmd/strand/prefetch.go:247-256` calls that check before append, without access to the pipeline-selected key. Trigger: a no-PK table has two eligible one-column UNIQUE keys and the sidecar chooses one while the pipeline chooses the other (or a composite key is selected in a different order). The check accepts both; replay's MySQL delete uses the writer's registered column names and the spool's values (`internal/writer/writer.go:733-741`), so a delete or key-changing update can address the wrong row. **Proof:** code path and overlay unit test `TestReviewWrongSameLengthKey` prove length-only acceptance, not a full end-to-end DB replay. **Fix:** persist explicit identity mode and ordered key names with the spool records and compare with the actual consumer's resolved key, or rekey from complete images; otherwise fail closed for unverifiable keys.

2. **P1 — Different functional unique indexes are incorrectly treated as equivalent.** `internal/validate/constraint_compat.go:164-173` invokes `descriptorsMatch`, which compares flags and ordinary column names, never expression text (`:282-294`); MySQL catalog collection treats functional parts as expression flags and omits them from Columns (`:495-497`). Trigger: source UNIQUE on `lower(email)`, target UNIQUE on `lower(phone)`, each represented by HasExpr and no ordinary columns. Preflight accepts them; target MySQL upsert can collide on phone and overwrite a different source row. **Proof:** mock catalog overlay `TestReviewExpressionIndistinguishable` asserts unsafe acceptance; expression catalog shapes and consequence follow from code, with no live DB reproduction. **Fix:** compare authoritative expression/index semantics including relevant collation or treat expressions as inconclusive and reject.

3. **P1 — Ordinary seed schema snapshots are loaded as JSON archive sidecars.** `cmd/strand/prefetch.go:106-116` falls back unconditionally to `SchemaSnapshot`, even when no archive is selected; `cmd/strand/seed.go:210-216` passes the existing manifest field. E.g. mysqldump manifests set that field to the SQL dump (`internal/seed/mysqldump.go:313-319`), and mydumper sets it to metadata (`internal/seed/mydumper.go:258-270`). Trigger: default seed prefetch with such a manifest and no explicit `--archive-schema`. It fails before source catch-up with JSON parse/open error. **Proof:** overlay `TestReviewSQLSnapshotTreatedAsSidecar` reproduces parse failure without archive or network; inspected producers and CLI show reachability. **Fix:** use the explicit sidecar field/flag only, unless a snapshot is explicitly marked and validated as that format; skip sidecar loading for source-only prefetch.

4. **P1 — Quoted qualified DDL bypasses the immutable sidecar barrier.** `internal/reader/archive/reader.go:400-419` splits backticks into tokens, so `ALTER TABLE `app`.`accounts` ...` with a different default schema is not matched to sidecar table `app.accounts`. With MINIMAL table metadata, same-count, same-type column changes can pass `verifyAgainstIdentity` (`:435-447`, `:461-484`), causing later rows to be assigned stale column names or keys; the DDL GTID can be spooled and covered. **Proof:** overlay `TestReviewQuotedQualifiedDDL` proves this exact detector bypass; the downstream corruption scenario is inferred from the verification and assembly path, not live-binlog reproduced. **Fix:** use a robust SQL parser or conservatively reject DDL when table scope cannot be determined; bind a required, complete versioned identity to the exact archive interval and reject unverified generation transitions.

5. **P1 — PostgreSQL `NULLS NOT DISTINCT` is never inspected.** `internal/validate/constraint_compat.go:549-559` omits `pg_index.indnullsnotdistinct`; `:630-639` copies the always-false field. Trigger: nullable source column with ordinary UNIQUE and target with UNIQUE NULLS NOT DISTINCT. Source permits multiple NULL values but target permits one; preflight accepts and replication later fails on a duplicate-key error. **Proof:** overlay `TestReviewPGNullsMetadataOmitted` reproduces unsafe compatibility acceptance with mock catalog rows; query omission is directly visible, no live PG replay. **Fix:** query the real catalog flag when supported, account for server versions, and fail closed if null equality semantics cannot be established.

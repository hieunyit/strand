# Báo cáo P1-13 — Seed từ mydumper và CLONE
Trạng thái: NOT DONE

## Kế hoạch
Hiện thực Seeder cho công cụ `mydumper` và `clone` trong module `internal/seed`:
- `seed plan` cho mydumper:
  - Đọc vị trí P từ file `metadata` của mydumper (`SHOW MASTER STATUS` / `SHOW BINARY LOG STATUS`, `Log`, `Pos`, `GTID`).
  - Đối chiếu chéo với target đã restore / load (SD-1).
  - Tạo `seed.json` hợp lệ theo `schema/seed.schema.json`.
- `seed plan` cho CLONE:
  - Đọc vị trí P từ thông tin clone hoặc `gtid_executed` sau khi clone hoàn tất.
- Từ chối 100% backup hỏng:
  - Thiếu file `metadata` hoặc thiếu GTID.
  - GTID có khoảng trống (holes) hoặc log gap (SD-2).
- Từ chối 100% mydumper chạy chế độ `NO_LOCK`:
  - Nếu file metadata chứa `Lock Mode: NO_LOCK` hoặc `--no-locks` hoặc `sync_thread_lock_mode = NO_LOCK`, từ chối ngay lập tức vì không đảm bảo tính nhất quán của snapshot (SD-1, spec/02 §9).

File sửa/tạo:
- `internal/seed/mydumper.go`
- `internal/seed/clone.go`
- `internal/seed/mydumper_clone_test.go`
- `tests/acceptance/P1-13.sh`

AC → Test:
- AC1: `seed plan` đọc P từ metadata mydumper và CLONE, đối chiếu chéo → `TestSD1_SeedPlan_MydumperAndClone_CrossCheck`
- AC2: backup hỏng (thiếu file, sai GTID, log có khoảng trống) bị từ chối 100% → `TestSD2_MydumperAndClone_CorruptedBackup_Rejected`
- AC3: mydumper chế độ `NO_LOCK` bị từ chối 100% → `TestSD1_Mydumper_NoLock_Rejected`

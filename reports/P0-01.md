# Báo cáo P0-01 — Môi trường docker compose
Trạng thái: NOT DONE

## Kế hoạch
Dựng môi trường phát triển/thử nghiệm bằng Docker Compose gồm 7 service (`mysql-src`, `mysql-dst`, `pg-src`, `pg-dst`, `toxiproxy`, `victoriametrics`, `grafana`), cấu hình đúng GTID, binlog, read-only, wal_level và khởi tạo user `strand` theo S03 §2, §3, kèm target `up` và `down` trong Makefile.

File sẽ tạo/sửa:
- `dev/compose.yaml`
- `dev/init/mysql-src/01-init.sql`
- `dev/init/mysql-dst/01-init.sql`
- `dev/init/pg-src/01-init.sql`
- `dev/init/pg-dst/01-init.sql`
- `dev/toxiproxy.json`
- `dev/scrape.yaml`
- `Makefile`
- `tests/acceptance/P0-01.sh`

AC → Test:
- AC1: `make up` xong, mọi service healthy trong ≤ 300 s → `tests/acceptance/P0-01.sh` (kiểm tra cả 7 service đạt trạng thái healthy trong vòng 300s sau khi gọi `make up`).
- AC2: mysql-src: gtid_mode=ON, binlog_row_image=FULL, binlog_row_metadata=FULL → `tests/acceptance/P0-01.sh` (truy vấn mysql-src xác nhận các biến hệ thống).
- AC3: User `strand` có trên cả 4 DB; trên pg-src có REPLICATION → `tests/acceptance/P0-01.sh` (truy vấn mysql.user và pg_roles).
- AC4: mysql-dst: read_only=1, super_read_only=0 → `tests/acceptance/P0-01.sh` (truy vấn mysql-dst xác nhận read_only=1 và super_read_only=0).
- AC5: `make down` không để lại volume → `tests/acceptance/P0-01.sh` (thực thi `make down` và xác nhận không còn named volume nào của project).

# Báo cáo P1-10 — Snapshot chunk + range-state (MySQL)
Trạng thái: PASS

## Kế hoạch
Hiện thực module `internal/snapshot`:
- Range-state machine với 5 trạng thái (Pending -> Reading -> Rendezvous -> Flush -> Done) theo S02 §5 và D §6.1, đảm bảo bất biến RS-1 (target không bao giờ hiển thị một row cũ hơn trạng thái nó đã có) và RS-2 (watermark GTID: low = @@GLOBAL.gtid_executed -> SELECT ... ORDER BY pk -> high = @@GLOBAL.gtid_executed).
- Chia chunk: keyset walk / numeric range theo PK.
- Timeout SELECT của chunk: hủy câu query nếu vượt ngưỡng 5s, chia đôi chunk và thử lại. Khi chunk chỉ còn 1 row (`min_chunk_rows = 1`), không áp timeout.
- Giới hạn `max_chunk_bytes`: mặc định 64MB; row lớn hơn `max_chunk_bytes` không gây vòng lặp chia chunk nhờ `min_chunk_rows = 1`.
- Chunk đuôi `[b_last, +∞)`: đọc `max(pk)` sau low; khóa lớn hơn thuộc range "Xong" ngay từ đầu và apply thẳng từ stream.
- `snapshot add` dưới tải cập nhật dày: chạy song song snapshot table với stream binlog MySQL, buffer gộp row theo PK (chỉ giữ image cuối), rendezvous stream >= high, merge & flush trong một transaction duy nhất, kết quả đạt 0 lệch giữa source và target.

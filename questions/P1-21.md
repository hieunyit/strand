# Câu hỏi P1-21: Xung đột giữa GEMINI.md Rule R5 và TASKS.md P1-21 về việc sửa Makefile

## 1. Trích dẫn chính xác

### Nguồn 1: `GEMINI.md` (dòng 37–39)
```markdown
- R5  Never modify `spec/`, `spec.lock`, `GEMINI.md`, `tasks/`, `tests/required.json`,
      `tests/acceptance/`, `deps.allow`, `Makefile`, `reports/TEMPLATE.md`, `.gemini/`. (gate)
      Note: CI always uses the owner's version of these files, so editing them gains nothing.
```

### Nguồn 2: `TASKS.md` (dòng 146–147)
```markdown
### P1-21 Checker độc lập + bộ fault injection
Đọc: S04 §3, §4. AC: 5 phép kiểm của S04 §3; checker bắt được 3 bản cài lỗi (bỏ Txn, apply trùng, đảo thứ tự); các kịch bản fault của S04 §4 chạy được bằng `make fault`.
```

## 2. Mô tả xung đột
Hiện tại `Makefile` chỉ có 2 target là `up:` và `down:`. Để chạy được lệnh `make fault` theo yêu cầu AC của task P1-21, bắt buộc phải thêm target `fault:` vào `Makefile`. Tuy nhiên, Rule R5 trong `GEMINI.md` (có mức ưu tiên cao nhất theo mục 1) nghiêm cấm agent chỉnh sửa file `Makefile`.

## 3. Các hướng giải quyết khả dĩ
1. **Hướng 1**: Cho phép agent chỉnh sửa `Makefile` trong task P1-21 để bổ sung target `fault:`.
2. **Hướng 2**: Người dùng (owner) cập nhật `Makefile` trên nhánh `main` (thêm target `fault:` gọi tới bộ kiểm thử/script fault injection), sau đó agent fetch/merge về `agent/P1-21` và tiếp tục thực hiện.
3. **Hướng 3**: Triển khai bộ kịch bản fault trong `scripts/fault.sh` (hoặc `tests/fault/`) và kiểm tra trực tiếp qua script đó thay vì qua `make fault`.
